# 미니맵과 알림 자리

- `client/src/minimap.ts`: 미니맵이다. 맵 전체를 북쪽이 위인 채로 상자에 맞춰 줄여 그린다(2026-11-09 사용자 결정). 그리는 것은 다섯이다.
  - 분대가 본 칸의 지형. 보지 못한 칸은 비워 상자 바탕이 보인다.
  - 지금 시야(캠프와 살아 있는 대원). 본 땅보다 한 단계 밝게 칠한다(2026-11-11 사용자 결정). 본 땅만 고르게 칠하면 지금 보이지 않는 곳이 지켜보는 곳처럼 읽힌다. 본 땅은 메인 화면의 바닥색이 아니라 시야 색(`lit`)으로 칠한다. 바닥색은 보지 못한 바탕과 거의 같아(대비 1.11) 본 곳이 보이지 않는다. 메인 화면처럼 땅, 시야, 벽 차례로 그린다.
  - 본 목표: 캠프, 시설, 보급 상자, 탈출 지점
  - 대원과 지금 보이는 적. `World`가 메인 화면과 같은 위치(내 예측 위치, 동료와 적의 보간 위치)를 넘긴다. 대원 점에는 밝은 고리를 두르고 적 점에는 두르지 않는다(2026-11-11 사용자 결정). 4번 대원의 색이 병사의 몸 색과 비슷해, 고리가 없으면 대원이 적으로 보인다.
  - 메인 화면이 보고 있는 범위(옅은 테두리)
  - 스냅샷에 이미 있는 공개 정보만 쓰므로 안개 규칙은 메인 화면과 같다.
  - 지형은 칸 하나를 화소 하나로 그린 그림을 `World`의 벽 배열이 바뀔 때만 다시 만든다. `World`는 지형이 바뀔 때마다 배열을 새로 만든다.
  - 상자 크기와 자리는 CSS가 정한다. 폭(`--minimap-w`)은 화면마다 정한 최대 폭과 최대 높이 안에서 맵 비율을 따르고, 높이(`--minimap-h`)는 테두리 안쪽이 맵 비율이 되게 구한다. JS는 방마다 맵 비율(`--minimap-ratio`)만 알린다. 맵 크기가 방마다 달라서다. 처음에는 JS가 다음 프레임에 크기와 자리를 쟀는데, 화면 크기가 바뀐 직후의 점검이 옛 자리를 재 겹침으로 잡았다.
  - 그림의 화소 수는 브라우저가 알려 주는 상자 안쪽의 실제 화소 수(`ResizeObserver`의 `devicePixelContentBoxSize`)로 맞춘다. 상자 크기는 소수 CSS px이고 브라우저는 상자 끝과 테두리를 화소 경계에 맞추므로, 반올림한 CSS 크기에 화소 밀도를 곱하면 화소 밀도가 소수인 화면(Windows 150% 등)에서 그림 전체가 번진다. 알려 주지 않는 브라우저에서는 잰 크기를 반올림한다. 화소 밀도는 메인 화면처럼 2까지만 쓴다. 상자가 화면에 없을 때(크기 0)는 재지 않는다. 0으로 잰 크기를 굳히면 다시 보였을 때 1×1 그림이 상자만큼 늘어난다.
  - **미니맵이 보이는지는 `World.draw` 한 곳에서 정한다(`Minimap.show`).** 메인 화면이 맵 전체를 보이는 동안(M 키·지도 버튼, 투입 전, 작전 종료)과 터치 화면의 서랍이 열린 동안(`World.menuOpen`, `main.ts`의 `setMenu`가 알린다)에는 숨는다. CSS로 따로 숨기지 않는다. 그래야 `body.minimap-on`이 늘 "미니맵이 화면에 있다"는 뜻이다. 예전에는 서랍이 CSS로만 숨겨, 서랍을 연 채 착지하면 숨은 상자를 0으로 재고 그 크기가 굳었다(PR #26 리뷰).
  - 자리: PC는 지도 오른쪽 위, 경과 시간 상자 아래다. 터치 화면은 메뉴 버튼 줄 아래 왼쪽이다. 캔버스가 위쪽 줄(`.top-row`) 안에 있어, 줄이 꺾여 높아져도 그 아래 끝에 붙는다. PC에서는 `.top-row`가 상자를 만들지 않아 지도 기준으로 놓인다.
  - 누름을 받지 않는다. PC에서는 그 자리에서도 조준·클릭이 된다. 터치 화면에서는 조이스틱 자리와 겹친 부분(가로 화면에서는 미니맵의 대부분, 세로 화면에서는 아래쪽 3분의 1)을 누르면 조이스틱이 생긴다. 미니맵은 위쪽 줄 묶음(z-index 25) 안이라 조이스틱보다 위에 그려지므로, 조이스틱이 미니맵과 겹치는 동안에는 미니맵을 옅게 해 받침과 손잡이가 비쳐 보이게 한다(`body.stick-on-minimap`, 2026-11-11 사용자 결정).
  - 알림이 비켜 가는 자리. PC는 미니맵이 보이는 동안(`body.minimap-on`)만 비키고, 터치 화면은 기술 버튼 쪽과 미니맵 쪽을 따로 정한다.
    - PC는 미니맵 왼쪽 빈 자리의 가운데에 둔다. 아주 좁은 창(440px 이하)은 미니맵 아래다.
    - **터치 화면의 기술 버튼 쪽**: 기술 버튼이 보이는 동안(`body.skills-on`, 살아 있고 작전이 끝나지 않음. `main.ts`의 `updateUi`가 붙인다) 알림이 기술 버튼에 닿을 수 있는 화면에서는 오른쪽 아래 기술 버튼 무리(`--touch-skills-w`, 188px)만큼 오른쪽을 비운다. 미니맵이 보이는지(지도 보기, 서랍)와 관계없다. **닿는지는 방향이 아니라 높이가 정한다.** 기술 버튼 무리는 늘 화면 아래 190px이고, 알림 셋이 쌓였을 때 아래 끝은 229~323px이다(위쪽 줄이 몇 줄인지에 달림. 한글 글꼴과 CI 실행기 글꼴로 폭 320~412px의 세로 화면에서 잼). 그래서 가로 화면과 높이 520px 이하의 화면에서 비운다. 그보다 높은 세로 화면은 기술 버튼이 화면 아래에 있어 알림을 예전 자리(위쪽 줄 아래 가운데)에 둔다. 알림을 미니맵 아래로 내리면 가장 작은 세로 화면(320×533·568)에서 화면 아래의 기술 버튼에 닿았다.
      - 이슈 #27 전에는 미니맵이 보이고 폭이 521px 이상일 때만 비워, 폭 520px 이하의 가로 화면(480×320·520×300·400×360)과 지도 보기·서랍을 연 동안(533·568×320)에 알림이 기술 버튼의 위쪽을 덮었다. 그 뒤 방향으로만 가렸을 때는 가로세로가 같거나 세로가 조금 긴 짧은 화면(360×360·390×400, 분할 화면·작은 창)에서 덮었다(PR #40 리뷰 1, 2026-11-24).
      - 비우고 남는 폭이 200px에 못 미치는 화면(폭 403px 이하)은 알림을 한 줄씩 차례로 보인다. 320×300에서 남는 폭이 116px이라 알림 셋이 좁은 기둥으로 꺾여 화면 아래(413px)까지 내려갔다(PR #40 리뷰 3). 기술 버튼을 덮는 가운데 자리로 되돌리지 않는다. 기술 버튼은 싸우는 동안 늘 눌러야 하고 알림은 사라진다. CSS는 가장 앞 줄만 보이고, `main.ts`의 `toast`는 그 조건(`singleToast`, CSS와 같은 미디어 조건에 `skills-on`)에서 새 줄의 끝나는 때를 앞 줄이 끝난 뒤 3.5초로 잡는다. 처음에는 가장 새 줄만 보여, 같은 순간에 온 안내 가운데 앞의 것이 한 번도 보이지 않고 함께 끝났다(PR #40 재리뷰 가). 가장 앞 줄에는 줄 사이 여백(`.toast div + div`)이 없어 상자가 줄 하나 높이다(재리뷰 나). **미디어 조건을 바꾸면 `style.css`와 `main.ts`의 `singleToastScreen`을 함께 고친다.** 서랍을 연 동안에도 한 줄이다. 남는 폭이 넓어져도(400×360에서 280px) 320×300에서는 줄 셋이 화면 아래를 넘어 서랍이 밀려난다. 가장 긴 안내 한 줄도 CI 실행기 글꼴의 320×300에서는 아래 끝이 화면보다 2px 길다(분할 화면의 끝 크기라 그대로 둔다).
      - 높이 문턱 520px는 잰 값(513px)에 여유가 7px뿐이다. 더 올리면 실제 작은 휴대폰의 세로 화면(320×533·568, 기술 버튼까지 20~55px 남음)에서 알림이 116px로 좁아지므로 올리지 않았다(PR #40 재리뷰). 글꼴을 키운 기기에서는 알림이 길어져, 문턱 바로 위(높이 521px 이상)의 세로 화면에서 먼저 기술 버튼에 닿을 수 있다.
      - 서랍(폭 min(300px, 85vw))이 2·4번 칸을 다 덮는 화면(폭 412px 이하)에서는 서랍을 연 동안 오른쪽 끝의 1·3번 칸(`--touch-skills-edge-w`, 104px)만 비운다. 덮인 칸까지 비우면 알림만 좁아져 키가 커지고 그만큼 서랍이 짧아졌다(PR #40 리뷰 2). 아예 비우지 않으면 400×360에서 알림이 3번 칸을 덮는다. 413px에서는 4번 칸이 1px 보여 기술 버튼 무리를 그대로 비운다.
      - 같은 화면(가로 화면과 높이 520px 이하)에서는 미니맵도 기술 버튼 무리 왼쪽에서 16px 떨어져 끝나도록 폭을 줄인다(`--minimap-w`에 `100vw - 188px - 24px`). 폭 366px 이상은 42vw가 먼저라 그대로다. 320×300에서 가로로 긴 맵(70×38칸)의 미니맵이 4번 칸에 8px 걸쳤다(PR #40 리뷰 때 크기를 더해 찾음).
    - **터치 화면의 미니맵 쪽**: 미니맵이 보이는 동안 폭 600px를 넘으면 미니맵 옆도 비워, 미니맵과 기술 버튼 무리 사이의 가운데에 둔다. 미니맵 옆으로만 비키면 알림이 오른쪽으로 밀려, 높이 320px 안팎의 화면에서 기술 버튼 위쪽을 덮었다. 폭 600px 이하는 그 사이가 260px에 못 미쳐, 알림이 미니맵을 잠시 덮는다. 기술 버튼은 늘 눌러야 하지만 미니맵은 잠깐 가려도 된다.
    - 알림은 위쪽 줄 묶음의 flex 항목이라 `position:static`에서도 `z-index`가 들어 미니맵 위에 그려진다. `relative`로 바꾸면 PC용 `top`·`left`가 살아나 알림이 밀린다. 터치 화면의 알림은 폭을 글자만큼으로 굳히지 않아(`width:auto`), 양옆 여백을 뺀 자리 안에서 저절로 꺾인다.
    - 서랍을 연 동안에는 미니맵이 숨어 `minimap-on`도 빠지므로 미니맵 쪽은 비키지 않는다. 기술 버튼 쪽은 비운다(폭 413px 이상은 기술 버튼이 서랍 옆에 보이고, 그보다 좁으면 위의 1·3번 칸만). 서랍은 위쪽 줄과 알림 아래에서 시작해, 알림 자리가 바뀌면 서랍 높이도 바뀐다.
    - `minimap.spec.ts`의 휴대폰 검사가 크기마다(가로 화면 열넷(폭 문턱 양옆 403·404px 포함), 세로 화면 아홉(짧은 화면 둘, 높이 문턱 양옆 520·521px, 세로 태블릿 포함), 맵 비율 셋) 알림이 쓸 수 있는 폭을 정확히(화면 − 16 − 미니맵 쪽 − 기술 버튼 쪽, 420px까지) 보고, 비우는 화면에서는 알림이 가장 넓어졌을 때의 오른쪽 끝이 기술 버튼 무리의 왼쪽 안인지, 보이는 알림 줄(한 줄 화면에서는 가장 앞 줄, 위쪽 여백 없음)을 본다. 지도 보기·서랍을 연 동안에도 일곱 크기에서 보이는 기술 버튼(서랍 밑에 다 들어간 칸은 뺀다)과 여백을 본다. 400×360에서 같은 스냅샷에 온 안내 둘이 차례로 3.5초씩 보이는지도 본다.
  - 색과 목표를 그리는 규칙은 메인 화면과 함께 `palette.ts`에 있다(지도·대원·적 몸·상성 색, 부순 시설·기다리는 보급 상자의 회색, 윤곽, 탈출 구역 반지름, 시설·보급 상자의 색과 그리는 조건). 한쪽만 바꾸면 두 화면이 말없이 달라진다. 여러 규칙이 함께 쓰는 배치 값(`--map-inset`, `--minimap-h`, `--touch-skills-w`, `--touch-skills-edge-w`, `--map-top`의 기본값)도 CSS 변수 한 곳에 둔다.
  - 방을 나갈 때 지난 방의 지도·미니맵·HUD를 비우는 규칙(`leave()`, `firstTexts`)은 구현이 있는 `main.ts`를 따라 `client-main.md`에 있다.
  - `minimap.spec.ts`가 그린 화소(시야와 고리 포함), 숨는 때, 벽이 바뀔 때 다시 그리기, 맵 비율, 그림의 화소 수(소수 배율, 화소 밀도 3), 화면에 없을 때 재지 않기, 방을 나갔다 들어오기, PC·휴대폰의 자리와 겹침, 조이스틱이 겹칠 때 옅어지기, 서랍을 연 채 착지하기를 본다.
