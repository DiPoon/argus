# ARGUS

PC와 휴대폰 브라우저에서 플레이하는 1–4인 협동 PvE. C# 서버가 이동·근접 RPS·피해·마나·시야·임무를 계산하고 TypeScript/PixiJS 클라이언트가 입력과 화면을 담당한다.

## 실행

.NET 10 SDK와 Node.js 24 이상이 필요하다. Linux/WSL에서도 실행할 수 있다. 저장소 루트에서:

```bash
npm --prefix client ci
npm --prefix client run build
dotnet run --project server/Argus.Server --urls http://127.0.0.1:5077
```

브라우저로 <http://localhost:5077>에 접속한다. 호출명과 장비(타격·방어·잡기 칸마다 앞만 보는 기술이나 둘레 기술, 자유 칸에 하나 더)를 고르고 **새 작전 시작 → 캠프 선택 → 5초 후 투입**을 누른다. **투입 마나는 0이므로 캠프 오른쪽 아래 보급 상자에 접근해 충전**한다. 휴대폰에서는 둘레 기술만 고른다(아래 "휴대폰").

친구는 같은 서버 주소에서 6자리 방 코드를 입력한다. 다른 PC와 시험하려면 서버를 `--urls http://0.0.0.0:5077`로 실행하고 해당 PC에서 접속 가능한 서버 주소를 사용한다. 방 코드만으로 다른 PC의 localhost에 연결되지는 않는다.

휴대폰으로 시험할 때도 휴대폰이 서버 주소에 닿아야 한다. 같은 공유기라면 위처럼 `0.0.0.0`으로 실행하고 PC의 사설 주소로 접속한다. WSL2에서는 휴대폰이 WSL 안의 서버에 바로 닿지 않는다. Windows의 포트 전달(portproxy)과 방화벽 규칙이 필요한데, 2026-11-01 시험에서는 둘 다 넣어도 닿지 않았다. 그럴 때는 임시 터널이 간단하다.

```bash
cloudflared tunnel --url http://127.0.0.1:5077
```

출력된 `https://….trycloudflare.com` 주소를 휴대폰에서 연다. 터널을 켜 둔 동안에는 주소를 아는 누구나 이 서버에 접속할 수 있으므로 시험이 끝나면 끈다. 터널로 온 접속은 서버에서 모두 127.0.0.1로 보인다. 그래서 방 수 상한에서 빠지고 참가 제한(분당 30회)은 모두가 함께 쓴다.

클라이언트 개발 중에는 서버를 5077로 켠 뒤 별도 터미널에서 `npm --prefix client run dev`를 실행하고 <http://localhost:5173>을 연다. Vite가 API와 WebSocket을 서버로 전달한다. 서버 시작점은 `server/Argus.Server/Program.cs`의 `Main`이다.

## 조작

| 입력 | 동작 |
| --- | --- |
| WASD / 방향키 | 이동. 기술 사용 중에도 가능 |
| 마우스 | 방향 지정 |
| 좌클릭 / 1 | 슬롯 1(타격): 근접 타격 또는 회전 베기 |
| 우클릭 / 2 | 슬롯 2(방어): 받아치기 또는 회전 방어 |
| Space / 3 | 슬롯 3(잡기): 근거리 잡기 또는 회전 잡기 |
| Q / 4 | 슬롯 4: 자유 칸에 고른 기술 |
| M | 전체 지도 |
| 보급 상자에 접근 | 체력·마나 보충, 부목표 회수 |

기술은 누를 때 한 번 나간다. 누르고 있는 동안에는 몸에 기운이 이어지고(최대 1초), 떼면 장판이 나간다. 누르고 있다고 기술이 다시 나가지는 않는다. 모든 기술이 마나 1을 소비하며 빗나가도 환불하지 않는다. 자연 회복은 없다. 기술은 한 번에 하나씩 사용한다. 둘레 기술(회전 베기·회전 방어·회전 잡기)은 조준하지 않고 대원 둘레의 적을 모두 친다. 셋은 상성 종류만 다르다. 슬롯 밖 사격과 재장전은 없다.

작전 중에는 지도 오른쪽 위의 미니맵이 맵 전체를 작게 보인다. 분대가 본 지형과 목표(캠프·시설·보급 상자·탈출 지점), 지금 시야(본 땅보다 조금 밝다), 대원(밝은 고리를 두른 점), 지금 보이는 적, 화면이 보고 있는 범위(옅은 테두리)다. M 키로 전체 지도를 보는 동안에는 숨는다.

### 휴대폰

손가락으로 조작하는 기기(브라우저가 `(pointer: coarse)`로 알리는 기기)에서는 터치 화면이 뜬다. 가로 화면에 맞췄다. PC에서도 주소에 `?touch`를 붙이면 볼 수 있다.

| 입력 | 동작 |
| --- | --- |
| 왼쪽 아래를 누르고 끌기 | 이동(조이스틱). 누른 자리가 가운데가 된다 |
| 오른쪽 아래 기술 버튼 넷 | 누르면 그 슬롯의 기술이 한 번 나간다. 누르고 있는 동안 기운이 이어지고, 떼면 장판이 나간다. 다른 손가락으로 조이스틱을 밀며 누를 수 있다 |
| 지도 누르기 | 투입 대기 중에 투입 위치 고르기. 기술은 나가지 않는다 |
| ☰ 메뉴 · 지도 · 전체 화면 | 옆 패널(임무·분대·버그 제보·나가기), 전체 지도, 전체 화면 |

- 로비에서는 둘레 기술만 고른다. 손가락으로는 조준하면서 기술을 쓰기 어렵기 때문이다. 종류 칸은 회전 베기·회전 방어·회전 잡기로 정해지고, 자유 칸에서 셋 가운데 하나를 고른다. 화면의 선택만 줄인 것이고, 서버는 PC와 같은 규칙으로 장비를 받는다.
- 안드로이드 크롬은 작전을 시작하거나 참가할 때 전체 화면으로 주소창을 숨기고 가로로 고정한다. 로비와 작전 화면의 "전체 화면" 버튼으로 끄고 켠다. 아이폰 사파리는 페이지 전체 화면을 지원하지 않아 버튼이 없다.
- 카메라는 늘 대원을 화면 가운데에 둔다. 지도 끝에서도 대원이 구석의 버튼 밑에 그려지지 않는다.
- 미니맵은 메뉴 버튼 줄 아래 왼쪽에 있다. 누름을 받지 않아, 조이스틱 자리와 겹친 부분(가로 화면에서는 미니맵의 대부분)을 누르면 조이스틱이 생긴다. 조이스틱이 미니맵과 겹치는 동안에는 미니맵이 옅어져 조이스틱이 비쳐 보인다. 지도 버튼으로 전체 지도를 보거나 ☰ 메뉴를 연 동안에는 숨는다.
- 임무 진행(시설 n/3, 부목표 보급품 n/2)을 메뉴 버튼 아래에 작게 보인다. 시설을 모두 부순 뒤에는 경과 시간 아래에 탈출이 더해진다. 탈출 지점을 아직 찾지 못했으면 "탈출 지점 찾기", 찾았으면 확보한 시간이다. 창 폭이 760px 이하라 옆 패널이 숨는 PC 화면에서는 경과 시간 옆에 한 줄로 보인다.

## 전투와 임무

- **타격은 잡기를, 잡기는 방어를, 방어는 타격을 이긴다.** 상성 색은 빛의 3원색이다(타격 빨강, 방어 파랑, 잡기 초록). 기술 버튼과 장비 칸에는 가위바위보 손 그림이 붙는다(타격 가위, 방어 주먹, 잡기 보). 가위가 보를 이기듯 타격이 잡기를 이긴다. 적의 예고 이름·색·방향·진행률을 보고 대응한다.
- **기술에는 몸에 도는 기운과 범위에 깔리는 장판이 있다.** 기술을 누르면 먼저 몸에 기운이 돌고, 조금 뒤 장판이 나가며 기운은 사라진다. 적은 예고하는 동안 기운이 돌고, 예고한 자리에 장판이 나간다. 화면에는 기운이 몸 둘레의 빛으로, 장판이 깔릴 자리가 옅은 범위로 보인다.
- **적의 예고 장판 안에서 그 장판을 이기는 기술을 누르면 그 순간 처치한다(완벽 대응).** 거리나 때를 맞출 필요가 없다. 그 기술은 장판 없이 끝나 바로 다음 기술을 쓴다. 종류가 다른 예고가 겹치면 맞는 버튼으로 하나씩 차례로 받아친다. 누를 때마다 마나가 든다.
- 틀린 버튼은 누른 순간에는 아무 일도 없다. 내 장판이 나가 그것을 이기는 기운의 적에게 닿으면 나만 피해를 받고 기술이 끊긴다. 끊겨도 바로 다음 기술을 쓸 수 있다. 같은 종류의 장판과 기운이 닿으면 비긴다.
- 작전 맵은 방마다 새로 만든다. 병사와 엘리트(분쇄자·철위병)가 나오고, 적 선딜은 타격 0.85초, 방어·잡기 0.95초다.
- 일반 적에게 이기면 피해 없이 처치, 비기면 서로 피해 1, 지면 나만 피해 1이다. 무행동인 적에게는 일반 피해 1이다. 장판이 나간 적(공격 창)과 회복 중인 적도 기운이 없어 같다.
- 받아치기는 방어의 기운이 앞 120°로 0.55초 돈 뒤 상성 없는 일반 반격이 장판으로 나간다. 받아칠 장판이 없었어도 반격하며, 상성 패배 시에는 취소한다. 완벽 대응을 내면 거기서 끝나 반격이 없다. 잡기는 한 번에 한 명만 판정한다.
- 기운은 기술이 향한 쪽(둘레 기술은 모든 방향, 그 밖에는 앞 120°)으로 돌고 기술의 사거리와 관계없다. 내 장판이 닿지 않는 거리의 적이라도 그 적의 장판이 나를 덮으면 기운으로 받아친다.
- 적은 예고하는 동안 노린 대원 쪽으로 돈다. 노린 대원은 걸어서 비켜 서도 상성으로 판정받는다. 피하려면 사거리 밖으로 물러나거나 벽 뒤로 숨는다. 다른 대원을 노리는 적을 옆에서 치면 상성 없이 일반 피해 1이다.
- 엘리트의 **Ⅱ** 예고는 이기는 기운 두 개가 필요하다. 동료와 함께 장판 안에서 이기는 기술을 누르고 있으면 그 순간 완벽 대응이다. 완벽 대응은 엘리트를 처치하고 같은 장판 안의 다른 동료까지 보호한다. 혼자면 예고 중에는 아무 일도 없고, 장판이 실제로 닿을 때 부분 대응이 난다. 나는 1을 잃고 엘리트도 1을 잃으므로, 두 번이면 혼자서도 쓰러뜨린다. 엘리트의 Ⅰ 행동은 혼자 완벽 대응할 수 있다.
- 분쇄자는 타격 Ⅱ, 철위병은 방어 Ⅱ를 사용한다. 엘리트의 몸 색이 그 2티어 행동의 색이다(분쇄자 빨강, 철위병 파랑). 엘리트 출현과 적 선딜 배율은 `Rules.cs`에서 조정한다.
- 아군끼리는 겹치며 피해를 주지 않는다. 적과 플레이어, 적끼리는 몸으로 길을 막는다.
- 시설 3곳을 타격이나 반격으로 부순 뒤 캠프 맞은편의 탈출 구역에 한 명 이상이 20초 머물면 성공한다. 부목표 보급품 2개는 선택 사항이다. 벽도 타격으로 파괴할 수 있다.
- 지도는 분대가 본 곳만 보인다. 처음에는 캠프 둘레만 보이고, 걸어 다니며 본 곳이 넓어진다. 시설·보급·탈출 지점도 직접 찾아야 한다.
- 첫 투입·난입·증원 모두 분대가 본 곳에만 할 수 있고, 위치 확정 후 5초가 걸린다. 미선택이면 계속 대기하며 기본 무적은 없다. 살아 있는 동료가 있으면 무제한 증원 가능, 전원 사망하면 실패, 솔로는 첫 사망에 실패한다.
- 보급은 유한하다. 캠프 상자는 분대가 함께 4번, 들판 상자는 상자마다 2번 쓰고, 시설을 부수면 그 자리에 2번 쓰는 상자가 생긴다. 상자는 쓴 사람만 채운다. 캠프에서 채운 마나로 들판 상자와 시설 자리 상자까지 나아가야 하며, 캠프에 머물면 결국 마나가 떨어진다. 시간이 지나 오는 전역 피해는 없다. 횟수와 체력 6·마나 24는 시험 수치다.

합의한 판정과 조정 가능한 수치는 [전투 명세](docs/combat.md), 전체 방향은 [요구사항](docs/requirements.md)에 기록했다. 원거리 기술·마력탄·광선·이전 총기·수류탄·터렛은 현재 기본기 출시 범위에 없다.

## 접속과 서버 권위

로그인 없는 게스트이며 방 코드로 진행 중 난입할 수 있다. 각 탭은 비밀 복구 토큰을 `sessionStorage`에 저장한다. 같은 탭 새로고침은 기존 상태로 복귀한다. 새 탭은 별도 게스트로 열 수 있으며, 탭 복제는 브라우저에 따라 같은 토큰을 복사할 수 있다.

끊긴 대원은 입력이 중단된 채 피격 가능한 상태로 120초 남는다. 재접속은 체력·마나·장비·기술·증원 시간을 유지한다. 같은 토큰의 새 연결은 이전 연결을 교체한다. 나가기는 복구 정보를 지우며 이전 자리는 유예 후 해제된다.

서버는 캠프와 생존 팀원의 시야를 합쳐 숨겨진 적의 위치·예고·효과를 직렬화 전에 제외한다. 분대가 본 곳의 맵·벽·시설·보급과 목표 진행은 공개 정보이고, 보지 못한 곳은 보내지 않는다. 서드파티 클라이언트용 [protocol v6](docs/protocol.md)를 제공한다. 이전 버전과 호환되지 않으므로 서버와 브라우저 빌드를 함께 갱신한다.

| `Game/MatchRecord.cs`, `Game/MatchReplay.cs` | 재현용 기록 한 줄과 기록 재생 |
| `Recording/` | 기록 파일 쓰기·보관 개수 정리·읽기 |
| `tools/Argus.Replay/` | 기록을 다시 돌려 보는 명령(저장소 루트 기준) |
| `client/src/main.ts` | 로비·네 슬롯 조작·터치 조작·HUD·재접속 |
| `client/src/world.ts` | 단순한 도형, 기운과 장판, 예고, 보간·이동 예측 |

서버 파일 경로는 `server/Argus.Server/` 기준이다. C#은 [작성 규칙](AGENTS.md)에 따라 명시적 타입과 일반 생성자, for/foreach와 if/else로 작성한다.

## 버그 제보와 재현

서버는 방마다 진행을 그대로 다시 돌릴 수 있는 기록을 `server/Argus.Server/recordings/`(Docker에서는 `/app/recordings`)에 남긴다. 최근 200개 방까지 보관하고, 제보가 들어온 방은 따로 200개까지 남긴다. 기록에는 방의 비밀 시드가 들어 있으므로 공개하지 않는다.

플레이 중 이상한 일이 생기면 왼쪽 패널 아래쪽의 "버그 제보"를 누른다(휴대폰에서는 ☰ 메뉴를 열면 나온다). 누른 순간이 기록되고, 알림에 방 코드와 틱이 나온다. 이어서 열리는 입력란에 무엇이 이상했는지 적어 "덧붙이기"를 누르거나 그냥 닫는다. 적는 동안에도 게임은 멈추지 않는다. 방 코드와 틱을 알려 주면 그 순간을 그대로 다시 볼 수 있다.

```bash
# 기록 파일 하나를 끝까지 다시 돌려 재현되는지 보고, 제보 목록을 본다
dotnet run --project tools/Argus.Replay -- server/Argus.Server/recordings/<시각>-<방 코드>.jsonl.gz
# 제보한 틱에서 멈춰 방 상태와 그 대원이 받은 스냅샷을 본다
dotnet run --project tools/Argus.Replay -- <기록> --until <틱> --snapshot <대원 id>
# 폴더의 기록을 모두 확인한다
dotnet run --project tools/Argus.Replay -- server/Argus.Server/recordings
```

같은 코드 버전으로 재생해야 같은 결과가 나온다. 기록 첫 줄에 기록한 서버의 커밋이 적혀 있다.

## 운영 범위

메모리 기반 단일 서버다. DB·영구 저장·성장·보상은 없으며 서버 재시작 시 방과 토큰이 사라진다. 디스크에는 재현용 기록만 남는다. 시뮬레이션은 1/30초 고정 틱으로 진행하고 상태 전송은 약 10Hz다. 서버 처리가 늦어지면 밀린 틱을 한 번에 8틱까지 이어서 진행한다. 방마다 비밀 시드가 있어, 같은 시드로 같은 틱에 같은 입력을 넣으면 같은 결과가 나온다. 기계가 달라도 같은지 CI가 확인한다. 리눅스(x64)에서 남긴 기록을 Windows(x64)와 macOS(ARM64)에서 다시 재생한다. 브라우저는 이동을 예측하고 서버 위치로 보정한다. 하드웨어 WebGL이 없으면 PixiJS Canvas 렌더러를 사용한다.

방 32개·방당 적 60마리는 설정 상한이며 부하 보장값이 아니다. 사운드와 정교한 밸런스는 아직 없다. Docker 설정은 로컬 5077을 노출한다. GKE 확장 전 방 배정·연결 라우팅·종료 절차·관측·부하 검증이 필요하다. 현재 여러 복제본 사이에 방 상태를 공유하지 않으므로 단일 인스턴스로 운영한다.
